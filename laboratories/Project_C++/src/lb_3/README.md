## 2. Теоретическая часть

### 2.1. Динамическая память и динамический массив
Динамический массив — это структура данных, хранящая элементы в непрерывном блоке оперативной памяти. В отличие от статического массива, размер которого жестко зафиксирован на этапе компиляции, динамический массив выделяет ресурсы в **куче (heap)** во время выполнения программы. Это позволяет контейнеру гибко изменять свою емкость по мере добавления новых данных.

### 2.2. Стратегия расширения и амортизированный анализ
Когда количество элементов в векторе достигает предела его выделенной памяти (`size == capacity`), добавление нового элемента требует перевыделения буфера. В классе реализуется **стратегия геометрического удвоения емкости** ($\times 2$). 

Благодаря такому подходу, ресурсоемкие операции по полному копированию элементов на новое место ($O(n)$) происходят все реже и реже по мере роста массива. В результате математического усреднения (амортизации) общие временные затраты равномерно распределяются по всей цепочке вставок, что гарантирует константную скорость операции `push_back` — **$O(1)$ амортизированно**.

### 2.3. Правило трех и правило пяти
Если класс управляет динамическим ресурсом через сырой указатель, автоматическая генерация методов компилятором приведет к утечкам памяти или краху программы из-за поверхностного копирования адресов. Необходим явный контроль:
*   **Правило трех (C++98):** Требует явного объявления *деструктора* (освобождение кучи), *конструктора копирования* и *оператора присваивания копированием* (создание независимой глубокой копии данных в памяти).
*   **Правило пяти (C++11):** Дополняет список *конструктором перемещения* и *оператором присваивания перемещением*. Они реализуют семантику перемещения: вместо дублирования данных они быстро «крадут» указатели у временных ($Rvalue$) объектов, зануляя донора, что кратно повышает производительность.

### 2.4. Итераторы
Итератор — это объект-посредник, предоставляющий унифицированный интерфейс для последовательного перебора элементов контейнера. Поскольку элементы динамического массива гарантированно лежат в памяти друг за другом, роль итераторов выполняют **сырые указатели (`T*`)**. Метод `begin()` возвращает адрес начального элемента, а метод `end()` указывает на воображаемый адрес *сразу за последним живым элементом* (`data + sz`), выполняя роль барьера остановки для циклов.

## 4. Листинг программы с комментариями

```cpp
#include <iostream>
#include <stdexcept>
#include <algorithm>

using namespace std;

// Шаблонный класс динамического массива
template <typename T>
class Vector {
private:
    T* data;    // Указатель на массив в динамической памяти (куче)
    int sz;     // Логический размер (число реально добавленных элементов)
    int cap;    // Физическая емкость (размер выделенного буфера памяти)

public:
    // 1. Конструктор по умолчанию (создает пустой вектор без аллокаций)
    Vector() : data(nullptr), sz(0), cap(0) {}

    // 2. Конструктор размера n (explicit запрещает неявное приведение типов)
    explicit Vector(int n) : sz(n), cap(n) {
        if (n < 0) throw invalid_argument("Размер не может быть отрицательным");
        data = (cap > 0) ? new T[cap] : nullptr;
        for (int i = 0; i < sz; i++) data[i] = T(); // Инициализация значениями по умолчанию
    }

    // 3. Конструктор копирования (Глубокое копирование выделенной памяти)
    Vector(const Vector& other) : sz(other.sz), cap(other.cap) {
        data = (cap > 0) ? new T[cap] : nullptr;
        for (int i = 0; i < sz; i++) data[i] = other.data[i];
    }

    // 4. Конструктор перемещения (Быстрая передача указателей за O(1))
    Vector(Vector&& other) noexcept : data(other.data), sz(other.sz), cap(other.cap) {
        other.data = nullptr; // Безопасно опустошаем донора, защищая его от деструктора
        other.sz = 0;
        other.cap = 0;
    }

    // 5. Деструктор (Своевременное освобождение ресурсов кучи при выходе из области видимости)
    ~Vector() {
        delete[] data;
    }

    // 6. Оператор присваивания копированием (Идиома Copy-and-Swap с защитой)
    Vector& operator=(const Vector& other) {
        if (this != &other) { // Защита от самоприсваивания (v = v)
            Vector temp(other);
            swap(temp);
        }
        return *this;
    }

    // Вспомогательный метод обмена значениями полей для Copy-and-Swap
    void swap(Vector& other) noexcept {
        std::swap(data, other.data);
        std::swap(sz, other.sz);
        std::swap(cap, other.cap);
    }

    // 7. Оператор присваивания перемещением (Семантика перемещения)
    Vector& operator=(Vector&& other) noexcept {
        if (this != &other) { // Защита от самоприсваивания (v = std::move(v))
            delete[] data;    // Предварительно очищаем собственные старые ресурсы
            
            data = other.data; // Присваиваем указатели донора
            sz = other.sz;
            cap = other.cap;
            
            other.data = nullptr; // Полное зануление указателей донора
            other.sz = 0;
            other.cap = 0;
        }
        return *this;
    }

    // Оператор индексации (Неконстантный — возвращает ссылку для чтения и ЗАПИСИ)
    T& operator[](int index) {
        if (index < 0 || index >= sz) throw out_of_range("Индекс вне диапазона");
        return data[index];
    }

    // Оператор индексации (Константный — строго для ЧТЕНИЯ из константных векторов)
    const T& operator[](int index) const {
        if (index < 0 || index >= sz) throw out_of_range("Индекс вне диапазона");
        return data[index];
    }

    // Геттеры доступа к приватным полям (Обеспечение инкапсуляции)
    int size() const { return sz; }
    int capacity() const { return cap; }
    bool empty() const { return sz == 0; }

    // Метод явного резервирования памяти для предотвращения частых аллокаций
    void reserve(int newCap) {
        if (newCap <= cap) return;
        T* newData = new T[newCap]; // Выделяем новый буфер
        for (int i = 0; i < sz; i++) newData[i] = data[i]; // Переносим живые элементы
        delete[] data; // Стираем старый массив
        data = newData;
        cap = newCap;
    }

    // Метод вставки элемента в конец (с автоматическим удвоением буфера при переполнении)
    void push_back(const T& value) {
        if (sz >= cap) {
            int newCap = (cap == 0) ? 1 : cap * 2;
            reserve(newCap);
        }
        data[sz++] = value; // Запись значения с последующим инкрементом размера
    }

    // Метод логического удаления последнего элемента за O(1)
    void pop_back() {
        if (empty()) throw underflow_error("Вектор пуст");
        sz--; // Сдвигаем границу видимости элементов назад
    }

    // Реализация итераторов (возвращают сырые указатели T*)
    T* begin() { return data; }
    T* end() { return data + sz; } // Указывает на адрес ЗА последним элементом
    const T* begin() const { return data; }
    const T* end() const { return data + sz; }

    // Индивидуальная функциональность Варианта 7: Линейный фильтр in-place
    void filter(bool (*predicate)(T)) {
        int writeIndex = 0; // Курсор записи валидных элементов
        for (int readIndex = 0; readIndex < sz; readIndex++) { // Курсор чтения всех элементов
            if (predicate(data[readIndex])) {
                data[writeIndex] = data[readIndex]; // Сдвигаем прошедшие проверку данные вперед
                writeIndex++;
            }
        }
        sz = writeIndex; // Корректируем размер вектора, отсекая отфильтрованный хвост
    }
};

// Функция-предикат: возвращает true, если переданное число четное
bool isEven(int x) {
    return x % 2 == 0;
}

int main() {
    setlocale(LC_ALL, "ru");

    cout << "=== Тестирование Vector ===" << endl;

    // Инициализация пустого вектора и вставка 10 элементов
    Vector<int> v;
    for (int i = 1; i <= 10; i++) {
        v.push_back(i);
    }

    // Вывод элементов (благодаря begin() и end() работает синтаксис range-based for)
    cout << "Исходный вектор: ";
    for (int x : v) cout << x << " ";
    cout << "\nРазмер: " << v.size() << " | Вместимость: " << v.capacity() << endl;

    // Применение фильтрации
    cout << "\nПрименяем фильтр (оставляем только чётные числа)..." << endl;
    v.filter(isEven);

    cout << "После filter (только четные): ";
    for (int x : v) cout << x << " ";
    cout << "\nНовый размер: " << v.size() << " | Вместимость: " << v.capacity() << endl;

    // Проверка корректности работы памяти после сжатия размера
    cout << "\nПроверка добавления нового элемента после фильтра:" << endl;
    v.push_back(99); // Должен безопасно перезаписать первый скрытый в памяти элемент
    cout << "После push_back(99): ";
    for (int x : v) cout << x << " ";
    cout << "\nФинальный размер: " << v.size() << " | Вместимость: " << v.capacity() << endl;

    return 0;
}
```

## 7. Ответы на контрольные вопросы

1. **Почему динамический массив называется «динамическим»?**
   Потому что он выделяет оперативную память в управляемой области — куче (heap) — во время выполнения программы. В отличие от статического массива, динамический умеет автоматически изменять свою емкость (`capacity`) прямо во время работы приложения, если текущий буфер переполняется.

2. **Что такое ёмкость (capacity) и чем она отличается от размера (size)?**
   Размер (`size`) — это количество элементов, которые были реально записаны в вектор на текущий момент. Емкость (`capacity`) — это суммарный физический объем памяти, выделенный под массив в куче. Емкость всегда больше или равна размеру; она показывает, сколько элементов вектор может принять до того, как ему понадобится перевыделение памяти.

3. **Почему при расширении массива ёмкость удваивается, а не увеличивается на фиксированное число?**
   Если увеличивать емкость на фиксированную величину (например, каждый раз делать $+10$), то при добавлении $n$ элементов операция аллокации памяти будет вызываться слишком часто. Это приведет к квадратичной суммарной сложности вставок $O(n^2)$ и увеличит среднюю стоимость одного `push_back` до линейной $O(n)$. Геометрическое удвоение ($\times 2$) снижает частоту перевыделений, сводя среднюю стоимость вставки к константной.

4. **Какова амортизированная сложность операции push_back? Почему?**
   Амортизированная сложность равна $O(1)$. Большинство вызовов метода проходят мгновенно за константное время, так как запись идет в уже зарезервированные пустые ячейки. Редкие и тяжелые операции выделения новой памяти и переноса данных ($O(n)$) равномерно распределяются (амортизируются) по всей длине цепочки вставок, сохраняя константную скорость в среднем.

5. **Что такое «правило трёх»? Когда оно применяется?**
   Правило трех утверждает: если класс управляет динамическим ресурсом (сырым указателем), программист должен вручную написать деструктор (для очистки памяти), конструктор копирования и оператор присваивания копированием (для выполнения глубокого копирования). Это предотвращает утечки памяти и критические ошибки двойного освобождения общего указателя разными объектами.

6. **Что такое «правило пяти»? Чем оно отличается от «правила трёх»?**
   Это расширение правила трех, принятое в стандарте C++11. Оно дополняет класс двумя новыми методами: конструктором перемещения и оператором присваивания перемещением. Отличие от правила трех заключается в поддержке семантики перемещения — возможности быстро «украсть» адрес памяти у временного, умирающего объекта ($Rvalue$), полностью исключая посимвольное глубокое копирование элементов.

7. **В чём разница между конструктором копирования и оператором присваивания?**
   Конструктор копирования создает и инициализирует совершенно новый, ранее не существовавшего объект на основе уже созданного донора. Оператор присваивания (`=`) вызывается для уже существующего, инициализированного объекта, из-за чего он перед копированием новых данных обязан сначала принудительно удалить свои старые динамические ресурсы, чтобы избежать утечки памяти.

8. **Зачем нужна проверка if (this != &other) in операторе присваивания?**
   Для защиты от самоприсваивания (например, `v = v;` или `v = std::move(v);`). Без этого условия объект на первой же строчке выполнения очистит свой собственный массив (`delete[] data;`), после чего попытается скопировать данные из уже уничтоженной области памяти, что приведет к неопределенному поведению и краху программы.

9. **Что такое итератор? Как он связан с указателем?**
   Итератор — это абстрактный объект-курсор, предоставляющий стандартный интерфейс для последовательного перебора элементов контейнера без раскрытия его внутреннего устройства. Так как динамический массив гарантирует непрерывное расположение элементов в памяти, обычный сырой указатель `T*` изначально обладает всеми свойствами итератора (поддерживает шаг `++`, разыменование `*` и сравнение `!=`).

10. **Зачем нужны методы begin() и end()?**
    Метод `begin()` возвращает итератор (указатель) на самый первый элемент вектора (индекс 0). Метод `end()` возвращает итератор на воображаемую ячейку оперативной памяти, находящуюся сразу за последним живым элементом (`data + sz`). Вместе они формируют полуоткрытый интервал `[begin, end)`, принятый во всех алгоритмах C++.

11. **Как реализовать range-based for для своего контейнера?**
    Для поддержки синтаксиса `for (int x : v)` класс контейнера должен содержать открытые публичные методы `begin()` и `end()`, которые возвращают указатели или объекты-итераторы, поддерживающие операции инкремента `++` (переход вперед), сравнения `!=` (проверка конца диапазона) и разыменования `*` (получение данных ячейки).

12. **Что такое «глубокое копирование»? Чем оно отличается от «поверхностного»?**
    При поверхностном копировании копируются только скалярные переменные-члены класса (включая адрес указателя `data`), из-за чего два объекта начинают делить один массив в куче. При глубоком копировании в куче выделяется новый, независимый блок памяти, куда посимвольно переносятся данные из оригинального массива донора, обеспечивая автономность объектов.

13. **Что такое семантика перемещения и зачем она нужна?**
    Семантика перемещения — это механизм оптимизации управления памятью, позволяющий быстро передавать права владения ресурсами между объектами. Она необходима для исключения дорогостоящих операций глубокого копирования в тех ситуациях, когда источник данных является временным или более ненужным объектом и его память можно просто забрать переназначением указателей.

14. **Почему конструктор перемещения помечается noexcept?**
    Модификатор `noexcept` гарантирует компилятору и алгоритмам, что операция переноса указателей не вызовет исключений. Это позволяет стандартным контейнерам применять скоростные оптимизации (например, быстро и безопасно перемещать элементы вместо долгого копирования при нехватке памяти в методе `reserve`).

15. **Как правильно освобождать память в деструкторе?**
    Поскольку динамический массив выделялся с использованием квадратных скобок оператора создания массивов `new T[cap]`, освобождать ресурсы в деструкторе необходимо строго парным оператором удаления массивов — `delete[] data;`. Одиночный оператор `delete` приведет к утечке памяти и неопределенному поведению (`Undefined Behavior`).
