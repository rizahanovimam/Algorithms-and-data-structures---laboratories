## Теоретическое обоснование

### 1. Отношения между классами

В объектно-ориентированном программировании классы редко существуют изолированно. Существует три основных типа отношений:

| Отношение | Характер связи | Пример |
|-----------|----------------|--------|
| Ассоциация | «использует», «знает о» | Врач → Пациент |
| Агрегация | «состоит из» (часть может жить без целого) | Автомобиль → Колёса |
| Композиция | «состоит из» (часть не может жить без целого) | Дом → Комнаты |

### 2. Композиция

**Композиция** — отношение «часть–целое», при котором «части» не могут существовать без «целого». Целое полностью контролирует время жизни частей.

Ключевая характеристика: **часть умирает вместе с целым**.

Реализация в C++:

- через поле-объект (часть создаётся внутри целого);
- через динамическое выделение памяти (`new` в конструкторе, `delete` в деструкторе);
- через умный указатель `std::unique_ptr` (рекомендуемый способ).

### 3. Агрегация

**Агрегация** — отношение «часть–целое», при котором «части» могут существовать независимо от «целого» и могут принадлежать разным «целым» одновременно.

Ключевая характеристика: **часть может существовать без целого**.

Реализация в C++: через указатели или ссылки на объекты, созданные снаружи. В деструкторе «целого» части **не удаляются**.

### 4. Сравнение композиции и агрегации

| Характеристика | Ассоциация | Агрегация | Композиция |
|---|---|---|---|
| Сила связи | Слабая | Средняя | Сильная |
| Время жизни частей | Независимое | Дольше или равное целому | Вместе с целым |
| Целое отвечает за уничтожение | Нет | Нет | Да |
| Целое отвечает за создание | Нет | Нет | Да |
| Каскадное удаление | Нет | Нет | Да |
| Реализация | Указатели, ссылки | Указатели | Поля-объекты, `unique_ptr` |

### 5. Статические члены класса

**Статическое поле** — принадлежит не отдельному объекту, а всему классу в целом. Существует в единственном экземпляре для всех объектов класса.

**Статический метод** — может быть вызван без создания объекта класса (`ClassName::method()`).

Особенности:

- статическое поле объявляется внутри класса ключевым словом `static`, а **определяется вне класса**: `int ClassName::field = 0;`;
- хранится в отдельной области памяти, а не в объекте;
- из статического метода можно обращаться только к статическим полям (нет `this`);
- изменить статическое поле из обычного метода можно — оно общее для всех объектов;
- статические счётчики используются для подсчёта количества живых объектов класса.

### 6. Паттерн «Одиночка» (Singleton)

**Одиночка** — порождающий паттерн проектирования, который гарантирует, что у класса есть только один экземпляр, и предоставляет к нему глобальную точку доступа.

Элементы реализации:

- приватный конструктор — нельзя создать объект извне;
- статическое поле `instance` — хранит единственный экземпляр;
- статический метод `getInstance()` — создаёт (лениво) и возвращает экземпляр;
- запрет копирования: `= delete` для конструктора копирования и оператора присваивания.

## Выполнение практической части

Реализованы:

- класс `Supplier` — поставщик (поля: название, страна);
- класс `Product` — товар (поля: название, цена, артикул) со **статическим счётчиком** `totalCount` и статическим методом `getTotalCount()`;
- класс `Warehouse` — склад, реализован как **Singleton** (приватный конструктор, `getInstance()`, запрет копирования), хранит `vector<Product*>` и `vector<Supplier*>` — **агрегация** (указатели на внешние объекты);
- в `main()` создаются товары и поставщики, склад получается через `getInstance()`, объекты добавляются на склад, после удаления склада товары и поставщики продолжают существовать.

### Код программы

```cpp
#include <iostream>
#include <string>
#include <vector>

// ============================================================
// КЛАСС SUPPLIER (Поставщик)
// ============================================================
class Supplier {
private:
    std::string name;
    std::string country;

public:
    Supplier(const std::string& n, const std::string& c)
        : name(n), country(c) {
        std::cout << "  [Поставщик] Создан: " << name
            << " (" << country << ")" << std::endl;
    }

    ~Supplier() {
        std::cout << "  [Поставщик] Удалён: " << name << std::endl;
    }

    std::string getName() const { return name; }
    std::string getCountry() const { return country; }

    void print() const {
        std::cout << "   - " << name << " (" << country << ")" << std::endl;
    }
};

// ============================================================
// КЛАСС PRODUCT (Товар) + СТАТИЧЕСКИЙ СЧЁТЧИК
// ============================================================
class Product {
private:
    std::string name;
    double price;
    std::string article;

    static int totalCount;              // статическое поле (подсчёт объектов)

public:
    Product(const std::string& n, double p, const std::string& a)
        : name(n), price(p), article(a) {
        totalCount++;                   // увеличиваем счётчик при создании
        std::cout << "  [Товар] Создан: " << name
            << " (арт. " << article << ", " << price << " руб.)"
            << " | Всего: " << totalCount << std::endl;
    }

    ~Product() {
        totalCount--;                   // уменьшаем при уничтожении
        std::cout << "  [Товар] Удалён: " << name
            << " | Всего: " << totalCount << std::endl;
    }

    std::string getName() const { return name; }
    double getPrice() const { return price; }
    std::string getArticle() const { return article; }

    static int getTotalCount() {        // статический метод
        return totalCount;
    }

    void print() const {
        std::cout << "   - " << name
            << " (арт. " << article
            << ", " << price << " руб.)" << std::endl;
    }
};

int Product::totalCount = 0;            // определение статического поля вне класса

// ============================================================
// КЛАСС WAREHOUSE (Склад) — SINGLETON + АГРЕГАЦИЯ
// ============================================================
class Warehouse {
private:
    static Warehouse* instance;         // единственный экземпляр (Singleton)
    std::string name;
    std::vector<Product*> products;     // агрегация: указатели на внешние объекты
    std::vector<Supplier*> suppliers;   // агрегация: указатели на внешние объекты

    Warehouse(const std::string& n) : name(n) {   // приватный конструктор
        std::cout << "=== СКЛАД \"" << name << "\" ОТКРЫТ ===" << std::endl;
    }

public:
    Warehouse(const Warehouse&) = delete;              // запрет копирования
    Warehouse& operator=(const Warehouse&) = delete;   // запрет присваивания

    ~Warehouse() {
        std::cout << "=== СКЛАД \"" << name << "\" ЗАКРЫТ ===" << std::endl;
    }

    static Warehouse* getInstance() {     // глобальная точка доступа
        if (instance == nullptr) {
            instance = new Warehouse("Центральный");
        }
        return instance;
    }

    void addProduct(Product* p) {
        products.push_back(p);
        std::cout << "  [Склад] Принят товар: " << p->getName() << std::endl;
    }

    void addSupplier(Supplier* s) {
        suppliers.push_back(s);
        std::cout << "  [Склад] Добавлен поставщик: " << s->getName() << std::endl;
    }

    void print() const {
        std::cout << "\n--- Склад \"" << name << "\" ---" << std::endl;

        std::cout << "Поставщики (" << suppliers.size() << "):" << std::endl;
        for (const auto* s : suppliers) {
            s->print();
        }

        std::cout << "Товары (" << products.size() << "):" << std::endl;
        for (const auto* p : products) {
            p->print();
        }

        std::cout << "Всего товаров в системе: "
            << Product::getTotalCount() << std::endl;
    }
};

Warehouse* Warehouse::instance = nullptr;  // определение статического поля вне класса

// ============================================================
// MAIN
// ============================================================
int main() {
    setlocale(LC_ALL, "ru");

    std::cout << "========== 1. СОЗДАНИЕ ТОВАРОВ И ПОСТАВЩИКОВ ==========\n";

    Product p1("Молоко", 89.90, "A001");
    Product p2("Хлеб", 45.50, "A002");
    Product p3("Сыр", 320.00, "A003");

    Supplier s1("Молочный комбинат", "Россия");
    Supplier s2("Хлебозавод №1", "Россия");

    std::cout << "\n========== 2. ПОЛУЧЕНИЕ СКЛАДА (Singleton) ==========\n";

    Warehouse* w1 = Warehouse::getInstance();
    Warehouse* w2 = Warehouse::getInstance();

    std::cout << "w1 == w2 (один и тот же склад): "
        << (w1 == w2 ? "ДА" : "НЕТ") << std::endl;

    std::cout << "\n========== 3. ДОБАВЛЕНИЕ НА СКЛАД (Агрегация) ==========\n";

    w1->addSupplier(&s1);
    w1->addSupplier(&s2);
    w1->addProduct(&p1);
    w1->addProduct(&p2);
    w1->addProduct(&p3);

    std::cout << "\n========== 4. СОДЕРЖИМОЕ СКЛАДА ==========\n";
    w1->print();

    std::cout << "\n========== 5. УНИЧТОЖЕНИЕ СКЛАДА ==========\n";
    delete Warehouse::getInstance();

    std::cout << "\n========== 6. ПОСЛЕ УНИЧТОЖЕНИЯ СКЛАДА ==========\n";
    std::cout << "Товары ВСЁ ЕЩЁ существуют (агрегация!):\n";
    p1.print();
    p2.print();
    p3.print();

    std::cout << "\nПоставщики ВСЁ ЕЩЁ существуют (агрегация!):\n";
    s1.print();
    s2.print();

    std::cout << "\nВсего товаров в системе: "
        << Product::getTotalCount() << std::endl;

    std::cout << "\n========== 7. КОНЕЦ ПРОГРАММЫ ==========\n";
    std::cout << "(Здесь удаляются товары и поставщики — локальные переменные)\n";

    std::cout << "\nНажмите Enter для выхода...";
    std::cin.get();

    return 0;
}
```

## Контрольные вопросы

**1. Что такое композиция? Приведите пример.**

Композиция — отношение «часть–целое», при котором части не могут существовать без целого: целое создаёт и уничтожает части. Пример: класс `House` содержит объекты `Room` (в примере из теории) или `Order`, внутри которого создаётся `Dish`.

**2. Что такое агрегация? Чем она отличается от композиции?**

Агрегация — отношение «часть–целое», при котором части существуют независимо от целого и могут принадлежать разным целым. Отличие: при композиции часть умирает вместе с целым (целое управляет памятью), при агрегации — нет (управляет внешний код).

**3. Как реализовать композицию в C++? Приведите пример кода.**

Через поле-объект или через указатель с ручным/автоматическим управлением:

```cpp
class Engine { public: ~Engine() { std::cout << "двигатель уничтожен\n"; } };
class Car {
    Engine* engine;
public:
    Car(int hp) : engine(new Engine(hp)) {}
    ~Car() { delete engine; }   // каскадное удаление
};
```

**4. Как реализовать агрегацию в C++? Приведите пример кода.**

Через указатель или ссылку на внешний объект; в деструкторе часть не удаляется:

```cpp
void Library::addBook(Book* book) { books.push_back(book); }
// в деструкторе Library книги НЕ удаляются
```

**5. В чём разница между временем жизни частей при композиции и агрегации?**

При композиции время жизни части равно времени жизни целого (удаляются вместе). При агрегации часть живёт дольше или независимо от целого — целое просто ссылается на неё.

**6. Что такое статическое поле класса? Чем оно отличается от обычного поля?**

Статическое поле принадлежит всему классу, существует в единственном экземпляре и не копируется в объекты. Обычное поле существует отдельно для каждого объекта.

**7. Как объявить и определить статическое поле? Где оно хранится?**

Объявляется в классе с ключевым словом `static`, определяется вне класса: `int Product::totalCount = 0;`. Хранится в статической (глобальной) области памяти, а не внутри объекта.

**8. Что такое статический метод? Можно ли из него обратиться к нестатическим полям?**

Статический метод вызывается через класс без объекта (`Product::getTotalCount()`). К нестатическим полям обратиться нельзя — у метода нет указателя `this`.

**9. Для чего используются статические счётчики объектов?**

Для подсчёта количества созданных/живых экземпляров класса (например, `Product::totalCount`), а также для сбора общей статистики всех объектов.

**10. Что такое паттерн «Одиночка» (Singleton)? Для чего он нужен?**

Паттерн, гарантирующий единственность экземпляра класса и предоставляющий глобальную точку доступа `getInstance()`. Нужен, когда ресурс должен быть общим (склад, конфигурация, подключение к БД).

**11. Как запретить создание копий объекта (конструктор копирования)?**

Объявить его как удалённый: `Warehouse(const Warehouse&) = delete; Warehouse& operator=(const Warehouse&) = delete;` — тогда компилятор выдаст ошибку при попытке копирования.

**12. В каком порядке вызываются конструкторы и деструкторы при композиции?**

Сначала конструктор целого, затем конструкторы частей (в порядке объявления полей). Деструкторы вызываются в обратном порядке: сначала части, затем целое.

**13. Можно ли изменить статическое поле из обычного метода?**

Да, можно — статическое поле общее для всех объектов, и любой метод класса имеет к нему доступ.

**14. Почему статические поля нужно определять вне класса?**

Потому что объявление в классе — только объявление (класс — это описание типа, а не объект). Определение вне класса выделяет память под поле и задаёт начальное значение; иначе возникнут ошибки линковки.

**15. В каких случаях стоит использовать композицию, а в каких — агрегацию?**

Композицию — когда часть не имеет смысла без целого и принадлежит только ему (комната в доме, элемент в контейнере). Агрегацию — когда часть существует независимо, может переиспользоваться или принадлежать нескольким целым (книга в разных библиотеках, товар на разных складах).
